1. APP OVERVIEW & PURPOSE
===============================================================================

CleanLoop is a waste management and environmental sustainability platform that:
- Connects users (waste generators) with drivers/collectors (waste management professionals)
- Enables users to request scheduled waste pickups
- Allows users to report illegal dumpsites/illegal waste dumping sites
- Provides real-time pickup tracking using GPS/maps
- Rewards users with points for eco-friendly contributions
- Includes a wallet system for currency and clean points
- Has different interfaces for regular users, professional users, drivers, and admins

Core Mission: Streamline waste collection and combat illegal dumping through technology

13. INTEGRATION POINTS (Frontend ↔ Backend)
===============================================================================

API COMMUNICATION:
  • All frontend API calls use Axios
  • apiAdapter.js provides fallback to localStorage for offline/demo
  • JWT tokens stored in localStorage
  • Authorization header: "Bearer {token}"
  • Multipart/form-data for file uploads

DATA FLOW:
  1. Frontend component dispatches action/API call
  2. Axios interceptor adds auth token
  3. Request sent to Django backend
  4. Backend validates JWT and authenticates user
  5. Backend processes request, queries database
  6. Response returned as JSON
  7. Frontend updates state (Redux/local state)
  8. UI re-renders with new data

ERROR HANDLING:
  • 401 Unauthorized → Redirect to login
  • 403 Forbidden → Show permission error
  • 400 Bad Request → Show validation errors
  • 500 Server Error → Show generic error, log to console

14. KEY BUSINESS LOGIC
===============================================================================

PICKUP ASSIGNMENT:
  • When user requests pickup → Backend randomly selects from active drivers
  • Creates notifications for both user and driver
  • Marks pickup as "assigned"
  • Driver can accept and change status to "in_progress"
  • On completion → status becomes "completed", user gets 100 points

POINTS CALCULATION:
  • Each completed pickup = 100 points (configurable)
  • Points awarded when pickup status = "completed"
  • Points can be viewed in wallet
  • Can be redeemed for rewards or currency conversion

VALIDATION RULES:
  • Scheduled time must be in future (not past)
  • Waste type must be from predefined list
  • Photo and address required for pickups
  • Description must be ≥10 characters for reports
  • Email must be unique (case-insensitive)
  • Password must be ≥6 characters
  • Phone number validation (format)

ADDRESS SEARCH:
  • Frontend sends address query to backend
  • Backend uses Nominatim API or similar to geocode
  • Returns coordinates (lat/lng)
  • Frontend plots on map

NOTIFICATION WORKFLOW:
  • Notifications created on specific events:
    - User creates pickup → driver notified
    - Driver accepts pickup → user notified
    - Pickup completed → both parties notified
    - System updates → relevant users notified
  • User can reply to notifications (stored in reply field)
  • Messages visible in notification detail

SUMMARY
===============================================================================

CleanLoop is a full-stack waste management application with:
  • 4 user roles (User, Professional, Driver, Admin)
  • Real-time GPS tracking for pickups
  • Gamified rewards system (points + wallet)
  • Illegal dumping reporting mechanism
  • Responsive design (mobile-first)
  • Theme support (Light, Dark, Orange)
  • Modern tech stack (React, Vite, Tailwind, Django, DRF)
  • Scalable architecture with separated frontend and backend

This document provides all information needed to rebuild CleanLoop using AI
assistants. Start with design/wireframes, then implement frontend components,
then backend APIs, then integration and testing.

Good luck with your rebuild! 🌍♻️
